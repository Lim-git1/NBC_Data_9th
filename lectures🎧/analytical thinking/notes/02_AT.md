
## 1. 가설

   - 가설은 **"So What?"** 에 답할 수 있어야함.
     - 우리가 통제할 수 있어야하고
     - 구체적이어야하고, 명확해야함
   - 좋은 가설은 검증이 가능하고, **행동**으로 이어져야한다.

### 좋은 가설의 3가지 조건: RSA

1. Relevant : 비즈니스 목표와 관련 있는가?
   - 이 가설 검증이 우리 팀/회의의 핵심목표(KPI, OKR)달성에 유의미한가?
2. Specific : 구체적인가?
   - 누가, 무엇을, 어떻게 했는지 명확하고 측정 가능한가?
3. Actionable : 실행 가능한가?
   - 가설이 맞거나, 맞지 않았을 때 다음에 해야할 행동이 명확해야함

### Relevant(관련성)

- RSA 중 R이 빠지면 결국 리소스를 낭비한셈
- R이 빠진 가설은, 검증에 성공하더라도 **비즈니스 임팩트**가 거의 없는 **우선순위 낮은 가설**
  - ex) 개인정보 페이지 아이콘을 변경하면 진입율이 10% 증가할 것이다 <- 매출증대에 기여도 낮음
  - 관련없는 거에 빠져서 디깅하는 것은 플젝 후 혼자 해봐라

## 2. 가설을 세웠다면? 검증하기!

   - "이 변화(원인)떄문에 이 결과(효과)가 나타났다" 를 밝혀내는 것


### A/B 테스트

   - A/B 테스트: 대조군(A) vs 실험군(B)
     - 사용자를 무작위로 두 그룹으로 나눈 후 Bias 없이 인과관계 증명


### A/B 테스트를 못하는 경우는?
1. 물리적/윤리적으로 불가능한 경우
   - ex) 흡연이 건강에 미치는 영향 (흡연을 강요할 수는 X)
   - ex) 버그가 이탈률에 미치는 영향(일부러 사용자 경험을 헤치며 버그를 노출할 수는 X)
2. 이미 원해서 선택한 경우
   - ex) 우리 서비스 유료 멤버십의 구매 증진 효과
     - 유료 멤버십을 원해서 가입한 사람은 원래 구매 의향/충성도가 높음

- 그래서 불가능한 경우에는 어떻게 하지?
  - 인과 추론(Causal Inference): 이미 관찰된 데이터만으로 공정한 비교를 할 수 있도록 보정하는 기법
    - "A/B Test를 했다면 어떤 결과가 나왔을까?" 를 추정하는 방법
    - PSM, DiD, RDD, Synthetic Control, ..
