## 1. [Bottom-Up] 데이터셋만 있을 때 

   - 데이터 받았으니 일단 EDA하면서 뜯어봐야지 ❌
   - 해당 기업이 '누구'에게 '어떤 행동'을 할지에 대한 결정을 돕기 위해, '어떠한' 주제를 정했다. 최종 산출물은 '무엇'이다 ⭕️

### 흐름

1. 이 데이터의 보고 대상이 누구일지 모색
2. 보고 대상이 누구한테? 어떤 의사결정에 도움을 줄지? 우리 아웃풋의 모양은 어떨지?
   - 모호하다면? 데이터 제공처의 비즈니스 모델이나 목표를 생각해본다.
     - 지금이 무슨 상황이고, 뭘 보고자 하는 거지? 왜 이 데이터를 줬을까? 이걸 통해 우리한테 원하는 게 뭘까?
3. 어떤 아웃풋이 의사결정을 도울 수 있을까?
   - 모델링? (이탈 예측 모델, 위험군 리스트)
   - 대시보드? (이탈률 현황 파악)
   - 인사이트 보고서?
4. 누구에게 전달하기 위한 결과물이지? 이걸 왜 요청했지? 무슨 상황이지? 내가 전달하고자 하는 메세지가 뭐지? 이걸 어떻게 더 효과적으로 표현하지?

## 2. [Top-Down] 문제가 주어졌을 때 (현업)

   - 데이터 받았으니 일단 SQL 열어보자 ❌
   - 모호한 '현상' 뒤에 숨겨진 '의사결정'을 찾는다 ⭕️

### 이 모호한 문제 뒤에 숨어있는 찐 의사결정 니즈가 무엇일까?

- 문제 -> 의사결정 -> 지표/모델 -> 산출물
X 일단 SQL 열어서 이것저것 해보자
- 이 모호한 '현상'뒤에 감쳐진 something 찾아.

### 흐름
1. 요청사항을 더 Scope (모호한 요청사항의 분석 범위 정하기)
   - 여기서 OOO용어의 정의가 무엇인가요? / 어떻게 계산되고 있나요? / 감소헸다는 것은 어떤 것과 비교한건가요?
   - '이렇다는건가~?' 안 됨. 유추/예측/추측 금지
2. 이 분석을 통해 어떤 의사결정이 필요할지 질문 (So What) (요청자의 needs에 맞게 움직여야함)

   - 나(해석자): 아! 지금 필요한건 x와 y의 어쩌구 분석이구나.

## 3. 악마의 변호사(Devil's Advocate)
나의 분석/논리의 모든 단계를 제3자(튜터, 심사위원, 적군, ..)의 입자가 되어서 신랄하게 공격해보기
1. 내 논리의 허점을 미리찾기.

   - ex) 현업에서는 로지스틱회귀 안 쓰고 다른 거 사용하는데 나는 왜 굳이 이걸 쓴거지?    
   - ex) 왜 군집에서 하필 K-means썼지? 얘는 이러저러한 단점이 있고, 이러저러한 상황에 쓰는 건데 나는 왜? 다른 애는 왜 안 썼지?


2. 이 데이터 믿을 수 있나?
   - 결과 왜이렇게 좋아..?
   - 각종 지표들의 기준은 나와 타인들이 동일한가?
3. 이 문제가 풀 가치가 있나?
   - 의사결정과 무관하게 나만 궁금한 거 아닐까?
   - 통계적으로 유의미(p-value < 0.05)해도 실제 비즈니스적 의미가 있나?
4. 이 결론이 진짜인가?
   - 운이 좋은 건 아닐까? 다른 내부/외부요인의 영향은 아닐까?

2. 문제 정의 단계에서의 로직트리(나만의 프레임워크) / 메트릭트리(?)
